Este documento reúne las entregas de la asignatura Ingeniería de Requisitos, donde se aplica el proceso formal de identificar, documentar y gestionar las necesidades de un sistema de software antes de comenzar su desarrollo.

La Ingeniería de Requisitos responde una pregunta fundamental antes de escribir código:

¿Qué debe hacer el sistema, para quién, bajo qué condiciones y con qué restricciones?

El proyecto elegido es ContractAI, una aplicación web con inteligencia artificial que permite a freelancers, emprendedores y PYMEs hispanohablantes generar, analizar y firmar contratos legales sin necesidad de contratar un abogado. Los requisitos se documentaron siguiendo estándares de la industria: IEEE 830, ISO/IEC 25010 y metodologías ágiles (Scrum).

1. Descripción del Proyecto

ContractAI es una aplicación web orientada a freelancers, emprendedores y PYMEs hispanohablantes que necesitan generar, analizar y firmar contratos legales sin contratar un abogado para cada documento.

  • Generar contratos a partir de plantillas inteligentes (servicios, NDA, empleo, sociedad, arrendamiento, compraventa, términos y condiciones, política de privacidad).
  • Analizar el riesgo de cualquier contrato existente y obtener un puntaje de 0 a 100 con cláusulas problemáticas resaltadas.
  • Personalizar contratos con asistencia de IA (Groq + LLaMA 3.3 70B).
  • Firmar digitalmente y guardar firmas reutilizables.
  • Compartir contratos vía enlace seguro.

Stack tecnológico:

Next.js 16 (App Router) React 19 TypeScript Tailwind v4 Groq AI · LLaMA 3.3 70B localStorage

2. Proceso de Ingeniería de Requisitos Aplicado

1
Identificación de actores

Se definieron los roles que interactúan con el sistema: Freelancer / emprendedor, PYME, Cliente final y Usuario registrado.

2
Elicitación — recolección de necesidades

Mediante observación del problema se redactaron las Historias de Usuario desde la perspectiva de cada rol.

Como [rol], quiero [acción], para [beneficio].
3
Análisis y derivación de Requisitos Funcionales

Cada HU se descompuso en capacidades concretas que el sistema debe ofrecer.

RF-NNN: El sistema debe [verbo] [objeto].
4
Definición de atributos de calidad

Se identificaron los atributos no funcionales (rendimiento, disponibilidad, usabilidad, seguridad) con métricas verificables.

RNF-NNN: El sistema debe [atributo medible].
5
Identificación de Reglas de Negocio

Se identificaron condiciones, restricciones y políticas que el sistema debe respetar.

RN-NNN: SI [condición] ENTONCES [acción / restricción].
6
Trazabilidad

Se construyó la matriz que conecta cada HU con los RF, RNF y RN correspondientes.

9. Conclusiones

1

Clarificación del alcance: La IR permitió separar lo imprescindible del MVP (generación, análisis, autenticación, firma) de lo opcional (chat IA, biblioteca de firmas, dashboard).

2

Restricciones técnicas identificadas: Desde el inicio se documentó el almacenamiento local en localStorage (RNF-007) y el uso de IA externa con fallback local (RN-009).

3

Métricas verificables: Los RNF incluyen valores concretos (tiempos de respuesta, tamaños mínimos, compatibilidad) que permiten probar el sistema objetivamente.

4

Anticipación de reglas críticas: El límite de 50.000 caracteres (RN-008) y el bloqueo de funcionalidades sin sesión (RN-001) se identificaron antes de implementar, evitando rediseños posteriores.

ENTREGA 2 — Casos de Uso · 16 de mayo de 2026

10. Contexto: NexaServicios S.A.S.

NexaServicios S.A.S. es la empresa cliente que implementará ContractAI para gestionar sus contratos comerciales internos. Actualmente elabora sus documentos en Microsoft Word sin plantillas estandarizadas, los distribuye por correo o WhatsApp, carece de control de versiones y el proceso de aprobación y firma es completamente manual.

Esta situación genera reprocesos, pérdida de información y falta de trazabilidad. ContractAI resuelve esta problemática ofreciendo una plataforma web que permite generar y analizar contratos de forma ágil, segura y centralizada.

11. Actores del Sistema

ActorDescripción

CoordinadorPersona con responsabilidad de supervisión sobre los contratos. Comparte las mismas funcionalidades que el Empleado.

CU-01: Registrar cuenta

CampoDetalle
Actor principalEmpleado / Coordinador de NexaServicios S.A.S.
DescripciónEl usuario crea una cuenta en ContractAI con sus datos básicos para poder acceder a las funcionalidades del sistema.
Precondiciones
  • El usuario no posee una cuenta registrada en el sistema.
  • El usuario dispone de un correo electrónico válido.
  • El sistema se encuentra disponible y operativo.
Flujo principal
PasoActorAcción
1UsuarioIngresa a la plataforma y selecciona Registrarse.
2SistemaPresenta el formulario con: nombre, correo electrónico y contraseña.
3UsuarioCompleta el formulario y confirma el registro.
4SistemaValida los datos y verifica que el correo no esté registrado previamente.
5SistemaCrea la cuenta y redirige al usuario a la pantalla de inicio de sesión.
Flujos alternativos
IDCondiciónRespuesta del sistema

Postcondiciones
  • La cuenta queda creada y activa en el sistema.
  • El usuario puede iniciar sesión con las credenciales registradas.
